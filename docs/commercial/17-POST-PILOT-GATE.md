# Post-pilot decision gate

Reunir evidence packet: success criteria, support/ticket summary, technical receipts, manual effort,
exit interview, qualification delta, pricing objection e decisão do cliente.

| Decisão | Quando escolher |
|---|---|
| DOUBLE DOWN | technical/operational pass, cliente renova, fit repetível e nenhum blocker recorrente |
| ADJUST ICP | produto funciona, mas o caso ideal apareceu em outro segmento ou o buyer errado foi abordado |
| ADD CAPABILITY | padrão repetido de blocker com receita/segmento claro e decisão de escopo explícita |
| HOLD | evidência insuficiente, cliente indeciso ou operação ainda depende de input externo |
| STOP/REPOSITION | falha de segurança/dados, economics inviável ou nenhum segmento demonstra valor |

## Regras

- Um único pedido caro não justifica roadmap sem frequência e impacto.
- Uma feature request não vira blocker por entusiasmo do vendedor.
- Incidente de dados ou incapacidade de restore encerra a promoção até remediação.
- Registrar a decisão, owner e data de revisão; não continuar pilotos indefinidamente sem gate.
